# 蓝牙遥控 + 手机App上位机 — 电赛全套方案

> 目标: 用 CH9141 BLE 模块实现 MSPM0G3507 小车与手机 App 之间的双向通信，
> 支撑 **远程遥控、参数在线调优、示教编程、数据可视化** 等电赛核心需求。

## 二、通信协议设计

### 2.1 数据包格式

```
┌──────┬──────┬──────┬───────────────────────────┬──────────┐
│ SYNC │ LEN  │ CMD  │         PAYLOAD           │  XOR8    │
│ 0xAA │ 1B   │ 1B   │       0 ~ 250 Bytes       │  1B      │
└──────┴──────┴──────┴───────────────────────────┴──────────┘

SYNC:   0xAA          固定帧头
LEN:    1 byte        PAYLOAD 长度 (不含 SYNC/LEN/CMD/XOR8, 0~250)
CMD:    1 byte        命令码
XOR8:   1 byte        LEN ^ CMD ^ PAYLOAD[0] ^ ... ^ PAYLOAD[N-1]
```

- 最小包: `AA 00 XX YY` (4 字节，无 payload)
- 最大包: `AA FA XX ... YY` (253 字节，payload 250)
- CH9141 单包上限 256 字节，本协议完全兼容

### 2.2 命令码分配

| 范围 | 类别 | 说明 |
|------|------|------|
| `0x00` | PING | 心跳/连接检测 |
| `0x01~0x0F` | 系统类 | 复位、版本查询、状态上报、页面查询 |
| `0x10~0x2F` | 运动控制 | 遥控、速度、转弯、急停 |
| `0x30~0x4F` | 参数读写 | PID参数、速度参数、传感器阈值 |
| `0x50~0x5F` | 路径示教 | 航点录制/回放 (原示教编程) |
| `0x60~0x6F` | 指令示教 | 指令脚本下载/执行/控制流 |
| `0x70~0x8F` | 遥测 & 调试 | TELEM_FRAME 推送 + DEBUG_MSG 调试信息 |
| `0xF0` | RAW | 透传通道 (调试/自定义) |

### 2.3 完整命令集

#### 系统类 (0x00~0x0F)

| CMD | 名称 | 方向 | Payload | 应答 |
|-----|------|------|---------|------|
| `0x00` | PING | App→MCU | 无 | `0x00`: ver_major, ver_minor, state |
| `0x01` | RESET | App→MCU | 无 | ACK 后软复位 |
| `0x02` | GET_STATE | App→MCU | 无 | state, error_code |
| `0x03` | ACK | 双向 | cmd_echo | 命令应答 |
| `0x04` | NACK | MCU→App | cmd_echo, err_code | 命令拒绝 |
| `0x05` | GET_HW_STATUS | App→MCU | 无 | 8 字节硬件状态位图 (见下方) |
| `0x06` | GET_PAGE_DATA | App→MCU | page_id(u8) | 按页面返回数据 (见页面查询协议) |

**状态码 (state)**:
- `0x00`: IDLE (空闲)
- `0x01`: RUNNING (任务运行中)
- `0x02`: RECORDING (示教录制中)
- `0x03`: PLAYING (示教回放中)
- `0x04`: ERROR (故障)
- `0x05`: CALIBRATING (校准中)
- `0x06`: INS_EXECUTING (指令执行中)

**GET_HW_STATUS 应答 (8 字节)**:

```
[0]: MCU flags     bit0=IMU_OK bit1=ENC_OK bit2=GRAY_OK bit3=MOTOR_OK
[1]: IMU_detail    WHO_AM_I 值 (0x68=正常, 0=故障)
[2]: ENC_detail    bit0=左编码器有脉冲 bit1=右编码器有脉冲
[3]: GRAY_detail   当前 digital 值 (0=全白/异常)
[4]: MOTOR_detail  bit0=左电机使能 bit1=右电机使能
[5]: ERR_code      0=无错误, 非0见错误码表
[6]: battery_volt  ADC 电池电压 ×10 (如 75=7.5V, 0=不支持)
[7]: uptime_s      MCU 运行秒数 (uint8, 0~255 循环)
```

**页面查询协议 GET_PAGE_DATA**:

App 发 `GET_PAGE_DATA(page_id)` → MCU 返回对应页面数据。

| page_id | 页面名称 | 应答 cmd | 应答数据 |
|---------|---------|---------|---------|
| `0x01` | 遥控/状态 | 0x06 | 硬件状态 + MCU 状态 + 编码器 + yaw (28 字节) |
| `0x02` | 电机调试 | 0x06 | 左右轮 PWM, 电流/速度, PID 当前值 (40 字节) |
| `0x03` | 陀螺仪 | 0x06 | roll/pitch/yaw, gyro_xyz, quaternion (36 字节) |
| `0x04` | 循迹调试 | 0x06 | 灰度 8 路原始值 + 归一化值 + 当前偏差 (30 字节) |
| `0x05` | 转弯调试 | 0x06 | 编码器差值 + yaw 角度 + 转弯状态 (16 字节) |
| `0x06` | 参数总览 | 0x06 | 所有 18 个参数当前值 (72 字节) |
| `0x07` | PID 详情 | 0x06 | 指定 PID 的 kp/ki/kd/kf + target/error/output/sum (36 字节, 需先设 PID 选择) |

**航点格式 (单条 12 字节)**:
```
[encL:i32] [encR:i32] [speed:u8] [action:u8] [timeout_ms:u16]
```

**Action 码**:
- `0x00`: MOVE_TO — 到达编码器位置
- `0x01`: TURN_L90 — 原地左转 90°
- `0x02`: TURN_R90 — 原地右转 90°
- `0x03`: WAIT — 等待 timeout_ms 毫秒
- `0x04`: LINE_TO — 循线段 (用灰度传感器)
- `0x05`: END — 序列结束标记

| CMD | 名称 | 方向 | Payload | 说明 |

| `0x63` | INS_DELETE | App→MCU | index(u8) | 删除指定位置指令 |
| `0x64` | INS_EXEC | App→MCU | 无 | 从 IP=0 开始执行 |
| `0x65` | INS_STOP | App→MCU | 无 | 停止执行 |
| `0x66` | INS_PAUSE | App→MCU | 无 | 暂停执行 |
| `0x67` | INS_RESUME | App→MCU | 无 | 继续执行 |

**指令格式 (单条 9 字节, 固定长度)**:

```
[Opcode:u8] [Param1:i16] [Param2:i16] [Param3:i16] [Param4:i16]
   Byte 0      1-2         3-4         5-6         7-8
```

> 固定 9 字节/指令, 250 条 = 2250 字节, 完整存于 SRAM 缓冲区。
> App 用 `INS_APPEND` 逐条下发, 用 `INS_CLEAR` 清空后重新编排。

**Opcode 全集**:

#### 一、直行类 (0x01~0x09)

| Opcode | 名称 | Param1 | Param2 | Param3 | Param4 | 实现依据 |
|--------|------|--------|--------|--------|--------|---------|
| `0x01` | MOVE_CM | dist_cm×10 | speed | — | — | **基础定速直行** — 编码器距离闭环, speed=恒定巡航 cm/s, 到场即停。适合短距离简单走位 |
| `0x02` | MOVE_RAMP | dist_cm×10 | — | — | — | **自动加速直行** — 软启动斜坡 (每帧 +0.5cm/s, 由 SET_RAMP 参数控制)、无固定速度上限 (硬封 80cm/s)、位置 PID 全程自由调速、末尾动态刹车 (按 SET_DECEL_DYNAMIC 参数减速), 高速时猛刹、低速时柔和 |
| `0x03` | MOVE_TRANSITION | dist_cm×10 | — | — | — | **直行→转弯无缝衔接** — 同 MOVE_RAMP 加速到末尾过渡区 (默认最后 ~15cm), 过渡区内**不刹车**、保持当前速度惯性, 到达 dist_cm 后直接切下一个转弯指令。专为高速切入转弯设计, 避免刹车再加速的延迟 |
| `0x04` | MOVE_IMU | dist_cm×10 | speed | yaw_kp×100 | — | **IMU 航向保持直行** (无黑线场景, 对角段风格) — 锁定当前 yaw 为基准, yaw PID 防偏, speed=巡航速度, Kp 默认 80 |
| `0x05` | MOVE_TIME | duration_ms | speedL×10 | speedR×10 | — | **定时行驶** N 毫秒, 可设左右差速 (用于微调或短脉冲测试) |

#### 二、旋转/转弯类 (0x10~0x19)

| Opcode | 名称 | Param1 | Param2 | Param3 | Param4 | 实现依据 |
|--------|------|--------|--------|--------|--------|---------|
| `0x10` | ROTATE_INPLACE_IMU | delta_deg×10 | speed | — | — | **原地旋转 (IMU yaw 闭环)** — 左右轮反向绕中心转, yaw PID 控到目标角度, 执行前自动 `YAW_RESET` (当前朝向→0°), 完成后 `POS_HOLD_LOCK` 锁止防惯性偏移 |
| `0x11` | ROTATE_INPLACE_ENC | delta_deg×10 | speed | — | — | **原地旋转 (编码器脉冲)** — 纯编码器差速, 左右轮反向, 计算左右轮脉冲绝对值之和 ≥ 目标差值即停, 到位后自动 PD 位置保持锁死 (Kp=1.5, Kd=0.3, deadband=3, max_output=800)。**IMU 故障时的降级方案** |
| `0x12` | ROTATE_ARC | radius_cm×10 | delta_deg×10 | speed | — | **边走边转 (弧线)** — IMU yaw 闭环, 内外轮差速走弧线, 转 delta_deg 度, 完成后重置 yaw |
| `0x13` | TURN_ENC_90 | direction | speed | — | — | **编码器差速 90° 转弯** — car.c `StartEncoderTurn` 风格: 两阶段 (盲转 300 脉冲不查线 → 寻线阶段用灰度 sensor 检测线), direction=1 左/2 右 |
| `0x14` | TURN_ENC_DIFF | diff_pulses | inner_spd×10 | outer_spd×10 | search_flag | **通用编码器差速转弯** — 完全自定义: 目标脉冲差值、内轮速度、外轮速度。search_flag=0 纯脉冲模式 (不查线, 到位即停并 PD 锁止), =1 两阶段寻线模式 (盲转→灰度找线) |

#### 三、循线类 (0x20~0x27)

| Opcode | 名称 | Param1 | Param2 | Param3 | Param4 | 实现依据 |
|--------|------|--------|--------|--------|--------|---------|
| `0x20` | LINE_FOLLOW | dist_cm×10 | speed | — | — | **灰度 PID 循线** — `Phase_LineFollow` 风格: 软启动 + 梯形减速 + 灰度 PID steer, 循黑线走够距离停止 |
| `0x21` | LINE_TO_INTERSECTION | speed | intersection_type | timeout_ms | direction | **循线直到路口** — 检测到指定路口类型时触发; direction: 0=停车, 1=左转, 2=右转 |

| `0x23` | LINE_ARC | dist_cm×10 | speed | steer_drop | — | **弧线循线 (动态降速)** — 同 LINE_FOLLOW 但根据 steer 实时降速: `speed -= steer × steer_drop/100`, 默认降 15% |

| `0x42` | SET_RAMP | accel_per_frame×10 | speed_limit | — | — | **软启动配置** — accel_per_frame=每帧加速量 (默认 5→0.5cm/s/周期), speed_limit=硬上限 (默认 800→80cm/s)。影响 MOVE_RAMP, MOVE_TRANSITION, LINE_FOLLOW 等带 ramp 的指令 |
| `0x43` | SET_DECEL_DYNAMIC | base_decel×10 | speed_coeff×100 | end_speed | — | **动态刹车配置** — base_decel=基础减速度脉冲/帧 (默认 2000→末尾 ~30cm 开始减速), speed_coeff=速度关联系数 (高速时膨胀减速区: decel_dist = base + speed×speed_coeff/100), end_speed=终点最低速度 (默认 10cm/s 防堵转异响)。影响 MOVE_RAMP, MOVE_CM, LINE_FOLLOW 等距离指令 |
| `0x44` | POS_HOLD_LOCK | kp×100 | kd×100 | deadband | release_flag | **PD 位置保持锁止** — 锁定当前编码器位置, PD 控制抵抗外力 (Kp 默认 150→1.5, Kd 默认 30→0.3, deadband 默认 3 脉冲)。release_flag=0 持续锁止直到下一个运动指令自动释放, =1 在下一个运动指令前**不释放** (需手动 DISABLE) |
| `0x45` | POS_HOLD_DISABLE | — | — | — | — | 手动解除位置保持锁止 |
| `0x46` | SLIP_COMP | enable | factor×100 | — | — | **打滑补偿** — enable=1 开启, factor=膨胀系数 (默认 10→10%)。开启后距离类指令按当前速度动态膨胀目标脉冲: `target_pulses *= 1 + speed × factor/(100×80)`, 补偿高速轮子打滑导致的实际距离不足 |

### 3.3 ble_protocol.c — 协议层设计

**核心数据结构**:

```c
#define BLE_RX_BUF_SIZE   256
#define BLE_TX_BUF_SIZE   256
#define BLE_PKT_TIMEOUT   100  // ms, 不完整包超时丢弃

typedef enum {
    PKT_SYNC = 0,    // 等待 0xAA
    PKT_LEN,         // 读取长度
    PKT_CMD,         // 读取命令
    PKT_DATA,        // 读取 payload
    PKT_XOR,         // 读取校验
} pkt_state_t;

typedef struct {
    pkt_state_t state;
    uint8_t     len;
    uint8_t     cmd;
    uint8_t     data_idx;
    uint8_t     data[BLE_RX_BUF_SIZE];
    uint8_t     xor_calc;
    uint32_t    last_byte_ms;
} ble_rx_ctx_t;

typedef struct {
    uint8_t  buf[BLE_TX_BUF_SIZE];
    uint16_t len;
    bool     busy;
} ble_tx_ctx_t;
```

**Packet 接收状态机**:

```
SYNC ──(0xAA)──> LEN ──(len)──> CMD ──(cmd)──> DATA ──(N bytes)──> XOR
  ↑                ↑               ↑               ↑                  │
  └────(timeout)───┴────(len>250)──┴──(bad cmd)────┴──(!= d_idx)──────┘
       超时复位         长度异常         非法命令         长度不匹配
                                                                     │
                              ┌──────────────────────────────────────┘
                              │
                              ▼
                          校验通过 → 调用 cmd_handler(cmd, data, len)
                          校验失败 → 丢弃, 回到 SYNC
```

**API 接口**:

```c
/* 协议初始化 */
void BLE_Protocol_Init(void);

/* 从 ISR 喂入接收到的字节 */
void BLE_Protocol_Feed(uint8_t byte);

/* 发送数据包 */
bool BLE_Protocol_Send(uint8_t cmd, const uint8_t *payload, uint8_t len);

/* 发送 ACK / NACK */
void BLE_Protocol_SendAck(uint8_t cmd);
void BLE_Protocol_SendNack(uint8_t cmd, uint8_t err);

/* 注册命令处理回调 */
typedef void (*ble_cmd_cb_t)(uint8_t cmd, const uint8_t *data, uint8_t len);
void BLE_Protocol_RegisterHandler(ble_cmd_cb_t cb);

/* 超时检查 (主循环调用) */
void BLE_Protocol_Poll(void);
```

**参数表实现思路**:
- 参数表是一个 `param_entry_t[]` 数组，每个条目指向实际的全局变量

```c
{
    BLE_Protocol_Poll();

    if (!g_ble_pkt_ready) return;

    switch (g_ble_pkt.cmd)
    {

    case 0x01: BLE_Cmd_Reset();               break;
    case 0x02: BLE_Cmd_GetState();            break;

    case 0x10: BLE_Cmd_MoveRaw(payload, len); break;
    case 0x11: BLE_Cmd_Stop();                break;
    case 0x12: BLE_Cmd_Emergency();           break;
    case 0x13: BLE_Cmd_Turn(payload, len);    break;
    case 0x14: BLE_Cmd_MoveDist(payload, len);break;
    case 0x15: BLE_Cmd_SetArcade(payload, len);break;
    case 0x16: BLE_Cmd_SetBaseSpeed(payload, len); break;
    case 0x17: BLE_Cmd_LineFollow(payload, len);  break;

    /* ---- 参数读写 ---- */
    case 0x30: BLE_Cmd_ParamRead(payload, len);  break;
    case 0x31: BLE_Cmd_ParamWrite(payload, len); break;
    case 0x32: BLE_Cmd_ParamSave();              break;
    case 0x33: BLE_Cmd_ParamLoad();              break;
    case 0x34: BLE_Cmd_ParamList();              break;

    /* ---- 示教编程 ---- */
    case 0x50: BLE_Cmd_TeachStart(payload, len); break;
    case 0x51: BLE_Cmd_TeachStop();              break;
    case 0x52: BLE_Cmd_TeachPlay(payload, len);  break;
    case 0x56: BLE_Cmd_TeachWaypoint(payload, len); break;
    case 0x57: BLE_Cmd_TeachClear(payload, len); break;
    case 0x5A: BLE_Cmd_TeachList();              break;

    /* ---- 遥测 ---- */
    case 0x70: BLE_Cmd_TelemStart(payload, len); break;
    case 0x71: BLE_Cmd_TelemStop();              break;

    default:
        BLE_Protocol_SendNack(g_ble_pkt.cmd, 0x01); // 不支持的命令
        break;
    }
}
```

### 3.6 app_teach.c — 示教编程设计

**数据结构**:

```c
#define MAX_WAYPOINTS     100      // 每个序列最多航点数
#define MAX_SEQUENCES     4        // Flash 最多存储序列数

typedef struct {
    int32_t encL;
    int32_t encR;
    uint8_t speed;
    uint8_t action;
    uint16_t timeout_ms;
} waypoint_t;

typedef struct {
    char        name[16];
    uint8_t     count;
    waypoint_t  wps[MAX_WAYPOINTS];
} teach_sequence_t;
```

**工作流程**:

```
一、录制模式:
   1. App 发 TEACH_START(20) → MCU 进入 TEACH_RECORDING
   2. MCU 以 20Hz 推送遥测帧到 App
   3. 用户在 App 端点击 "记录航点" → App 发 TEACH_RECORD_WP
      → MCU 记录当前 encL/encR/yaw/speed 为一个航点
   4. 或用户在 App 端实时控制小车运动，轨迹自动记录
   5. App 发 TEACH_STOP → MCU 退出录制
   6. App 发 TEACH_WAYPOINT 逐个下传航点到 MCU
   7. App 发 TEACH_SAVE → MCU 存入 Flash

二、回放模式:
   1. App 发 TEACH_LOAD(seq_id) → MCU 加载序列
   2. App 发 TEACH_PLAY(seq_id, speed_scale)
   3. MCU 顺序执行航点:
      - MOVE_TO: PID 控制走编码器位置
      - TURN: IMU yaw 闭环转弯
      - WAIT: 延时
      - LINE_TO: 启用灰度循线
   4. 每个航点执行完成 → MCU 发 ACK
   5. 全部航点完成 → MCU 发 "done" 事件
```

### 3.9 指令示教 (指令脚本解释器)

#### 概述

指令示教是路径示教的互补模式。用户不手推小车录制轨迹，而是在 App 上**可视化编排指令序列**，每条指令包含操作码和参数。脚本下载到 MCU 后由内置的解释器逐条执行。

| 对比 | 路径示教 | 指令示教 |
|------|---------|---------|
| 编程方式 | 手推录制轨迹 | App 选指令 + 填参数 |
| 控制精度 | 依赖人手推车轨迹 | 编码器/IMU 闭环, 精确 |
| 可编辑性 | 航点可增删 | 指令可任意增删改插 |
| 复用性 | 一个赛道一个序列 | 子序列可用控制流复用 |
| 适用场景 | 第一次跑赛道快速定型 | 精确竞赛, 复杂动作编排 |

#### 指令缓冲区

```c
#define INS_BUF_MAX  250   /* 最多 250 条指令 */

typedef struct {
    uint8_t  opcode;
    int16_t  p1, p2, p3, p4;   /* 4 个通用参数 */
} ins_t;

static ins_t  g_ins_buf[INS_BUF_MAX];
static uint16_t g_ins_count;   /* 当前指令总数 */
static uint16_t g_ins_ip;      /* 指令指针 (Instruction Pointer) */
```

#### 解释器主循环 (10ms 调用一次)

```
App_InsExecTask():
  if 暂停/停止 → return
  while 当前指令 != 执行中:
    读取 ins = g_ins_buf[ip]

    switch ins.opcode:
      MOVE_CM    → 设 targetSpeed + 编码器闭环, 标记"执行中", 记录起始编码器
      ROTATE_*   → 设 targetSpeed + IMU yaw 闭环, 标记"执行中", 记录起始 yaw
                    (执行前自动 YAW_RESET: 将当前 yaw 置为 0, 避免累计误差)
      WAIT_*     → 记录起始时间, 标记"等待中"
      LINE_*     → 设 targetSpeed + 启动灰度循线, 标记"执行中"
      JUMP       → ip = 查找标签(label_id), 继续
      JUMP_IF    → 判断条件 → 满足: ip=标签; 不满足: ip++
      IF         → 判断条件 → 不满足: ip=跳过到 ELSE/END_IF
      ELSE       → ip=跳到 END_IF (走了 if 分支就不走 else)
      FOR        → 初始化循环变量, push 循环栈, ip++
      END_FOR    → 循环变量+step, 判断 → 继续: ip=FOR+1; 结束: pop+ip++
      WHILE      → 判断条件 → 不满足: ip=跳到 END_WHILE
      END_WHILE  → ip=跳回 WHILE
      END_SCRIPT → 停止执行, 发 EVENT 0x02

    if "执行中/等待中":
      if 完成判定:  → 发 EVENT 0x00, ip++, 释放"执行中"
      else:         → break (下个 10ms 再检查)
```

#### Yaw 重置机制 (解决旋转指令累计误差)

每次 `ROTATE_INPLACE` 或 `ROTATE_ARC` 开始执行时:

```c
void Ins_YawReset(void)
{
    /* 记录当前 yaw 为新的 0 基准 */
    g_ins_yaw_base = g_imuData.yaw;

    /* PID 角度环目标清零 */
    PID_SetTarget(&pidAngle, 0.0f);

    /* 重新锁定航向参考 */
    g_ins_yaw_locked = false;
}
```

解释器中的 yaw 判断统一用相对量: `yaw_rel = g_imuData.yaw - g_ins_yaw_base`。
这样每次旋转都以"当前朝向为 0 度"开始, 不存在累加偏差。

### 4.3 页面数据查询机制

每个页面独立查询, 降低 MCU 负担:

```
App 行为                          MCU 行为
────────                          ────────
切换到 Tab2 (电机调试)             
  发 GET_PAGE_DATA(0x02)         → 打包电机数据 40 字节
                                  → BLE_Protocol_Send 一次性回复
  收到回复 → 更新 UI
                                  
用户拖动 PID 滑块                  
  发 PARAM_WRITE(id, val)        → 写入参数, ACK
                                  
用户点击 [刷新]                    
  发 GET_PAGE_DATA(0x02)         → 再次回复最新数据

切换到其他 Tab                     
  不发任何新请求                   (前一页数据自然过期)
```

**关键原则**:
- 切换 Tab → 发一次 GET_PAGE_DATA, 收完即停
- 需要更新 → 点 [刷新], 不自动轮询
- 唯一的连续通信: 遥控摇杆 (50ms) + 示教录制时遥测
- 每次回复 <= 72 字节, 单包不拆
- **参数初始值 = MCU 当前值**: 进入任何参数编辑页时, GET_PAGE_DATA 返回的就是 MCU 上正在运行的实际值 (可能已被之前调过), App 直接填入作为滑块和输入框的初始值, 不硬编码默认值

### 4.4 MCU 侧对应实现

新增 `app_page.c/h` 处理页面查询:

```c
void AppPage_HandleQuery(uint8_t page_id)
{
    uint8_t buf[72];
    switch (page_id) {
    case 0x01: // 遥控/状态页 (28 bytes)
        // hw_status[8] + state + encL/R + yaw + speedL/R
        break;
    case 0x02: // 电机调试页 (40 bytes)
        // PWM_L/R + target + actual_speed + enc + pid_all + pid_out
        break;
    case 0x03: // 陀螺仪页 (36 bytes)
        // roll/pitch/yaw + gx/gy/gz + ax/ay/az + q0-q3
        break;
    case 0x04: // 循迹调试页 (30 bytes)
        // gray_raw[8] + gray_normal[8] + digital + deviation
        break;
    case 0x05: // 转弯调试页 (16 bytes)
        // turn_inner/outer/target + diff + yaw + phase
        break;
    case 0x06: // 参数总览页 (68 bytes)
        // all 17 param values as float array
        break;
    }
    BLE_Protocol_Send(BLE_CMD_GET_PAGE_DATA, buf, len);
}
```

### 4.5 BLE 通信需求

| 需求 | 说明 |
|------|------|
| 设备扫描 | 扫描 BLE 设备, 过滤名称 "CH9141BLE2U", 显示信号强度 |
| 服务发现 | 连接后自动发现 UUID 0xFFF0 服务 |
| 写特征 | UUID 0xFFF2, 用于 App→MCU 发送数据包 |
| 通知特征 | UUID 0xFFF1, 先写 CCCD(0x2902) 使能, 用于 MCU→App 推送 |
| 断线重连 | 自动扫描并重连, 间隔 2s, 最多 5 次 |
| 心跳 | 每 2 秒发 PING, 连续 3 次无响应判定断开 |
| 页面查询 | 切换 Tab 发 GET_PAGE_DATA, 点刷新再发, 不轮询 |

### 4.6 协议码绑定

| CMD | 名称 | App 触发时机 |
|-----|------|-------------|
| 0x00 | PING | 定时 2s 心跳 |
| 0x05 | GET_HW_STATUS | 连接后首次 / 手动刷新 |
| 0x06 | GET_PAGE_DATA | 切换 Tab / 点 [刷新] |
| 0x10 | MOVE_RAW | 摇杆拖动时 50ms 周期 |
| 0x15 | SET_ARCADE | 摇杆释放→(0,0), 拖拽→周期发送 |
| 0x12 | EMERGENCY | 急停按钮 |
| 0x30 | PARAM_READ | 进入参数页时 |
| 0x31 | PARAM_WRITE | 滑块/输入框值改变 |
| 0x32 | PARAM_SAVE | "保存到 Flash" |
| 0x34 | PARAM_LIST | 参数总览页初始化 |
| 0x50-0x5C | TEACH_* | 示教录制/回放/航点管理 |
| 0x60-0x6C | INS_* | 指令示教编排/执行 |
| 0x70 | TELEM_START | [仅] 示教录制时 / 主动启用 |
| 0x71 | TELEM_STOP | 停止录制 / 切换页面 |

### 4.7 注意事项

- Android 需位置权限扫描 BLE (6.0+)
- CH9141 不需配对, 直接 GATT 连接
- 单包 <= 256 字节, 页面查询全部 <= 72 字节
- 除遥控和示教录制外, 不做实时轮询
- [刷新] 是唯一的主动数据获取方式
- 蓝牙断开时 App 须提示并停止所有周期发送


### 4.8 PID 调参指南与输入验证

每个 PID 参数的编辑界面需包含:
1. 调整方向提示 (一句话说清调大/调小的效果)
2. 数值输入框 + 范围限制 + 单位滑条 (粗细调)
3. 一键恢复默认 按钮

#### 4.8.1 速度环 PID (pidLeftSpeed / pidRightSpeed, 位置式, FF前馈)

| 参数 | 范围 | 默认 | 调大效果 | 调小效果 | 调试口诀 |
|------|------|------|---------|---------|---------|
| Kp | 0~200 | 60 | 响应更快, 到达目标速度更迅速; 过大则超调振荡 | 响应变慢, 加速无力; 过小则速度上不去 | 从 30 起步, 每次加 10, 直到听到轮子吱吱振荡声, 回退 20% |
| Ki | 0~50 | 0 | 消除稳态误差, 长时间跑更稳; 过大则积分饱和, 刹车延迟 | (默认0不启用) | 一般速度环不开积分, 保持 0 |
| Kd | 0~20 | 0.5 | 阻尼振荡, 刹车更稳; 过大则高频抖动, 电机发烫 | 振荡加剧, 刹车过头来回摆 | 振荡时逐步加, 0.1 步进, 到振荡消失为止 |
| FF | 0~50 | 8.0 | 前馈补偿, 起步更快; 过大则起步猛冲 | 起步慢, 空载和带载速度差异大 | 空载跑 30cm/s, 调到实际速度接近目标, 不宜超过目标速度 |

典型调参流程: FF 粗调 -> Kp 中调 -> Kd 精调, Ki 不动

#### 4.8.2 循迹环 PID (pidLine, 位置式, 无前馈)

| 参数 | 范围 | 默认 | 调大效果 | 调小效果 | 调试口诀 |
|------|------|------|---------|---------|---------|
| Kp | 0~0.01 | 0.00105 | 纠偏更强, 线弯时快速拉回; 过大则S形摆动 | 纠偏弱, 弯道容易冲出线 | 直道不摆, 弯道不冲, 从默认值 ±30% 范围试 |
| Kd | 0~0.001 | 0.00002 | 抑制摆动, 阻尼高频抖动; 过大则反应迟钝, 弯道拐不过去 | 摆动幅度大, 走直线也左右晃 | 有摆动时 0.000005 步进加, 到走直线稳定为止 |

典型调参流程: 先跑直道调 Kp 到不摆, 再跑弯道微调, 最后加 Kd 抑制残余摆动

#### 4.8.3 角度环 PID (pidAngle, 位置式, 预留)

| 参数 | 范围 | 默认 | 调大效果 | 调小效果 | 调试口诀 |
|------|------|------|---------|---------|---------|
| Kp | 0~5 | 0.165 | 航向纠正更猛; 过大则角度超调来回转 | 纠正慢, 风吹/路面不平容易偏 | 原地打转时调: 目标90度, 看实际超调量 |
| Kd | 0~1 | 0.01 | 减少过冲, 到目标角度更准; 过大则卡顿, 到不了目标 | 过冲大, 转超了才往回拉 | 超调 >5度 时加, 0.002 步进 |

#### 4.8.4 App 输入验证规则

```
参数           | 输入类型    | 验证规则
PID Kp/Ki/Kd  | 浮点数输入  | 限制在 [min, max]
PID FF        | 浮点数输入  | [0, 50]
BASE_SPEED    | 整数输入    | [0, 80]
TURN_INNER    | 整数输入    | [0, 60]
TURN_OUTER    | 整数输入    | [0, 80]
TURN_TARGET   | 整数输入    | [0, 5000]
GYRO_BIAS     | 浮点数输入  | [-500, 500]
LAPS          | 整数输入    | [1, 10]
GRAY_THR      | 整数输入    | [0, 4095]
```

输入框行为:
1. 输入时实时校验: 超范围则输入框红色边框 + 提示文字
2. 滑块联动: 拖动滑块 -> 输入框同步更新; 输入框输入 -> 滑块同步跳转
3. 点写入时: 再次校验 -> PARAM_WRITE
4. 每个参数旁边 [默认] 按钮: 一键填入默认值
5. 滑块步长: Kp/Kd 类用滑条 0.1 步进 + 输入框精确输入

### 4.9 参数写入时的双重验证

为防止误操作, 参数写入加入确认机制:

写入流程:
  用户改值 -> 点 [写入]
  -> App 检查值是否在 [min, max] 范围内
    -- 超出 -> 红色提示 "值超出范围 [min~max]"
    -- 合法 -> 发送 PARAM_WRITE
              -> MCU 回复 ACK -> App 显示 "写入成功" 绿色 Toast
              -> MCU 回复 NACK -> App 显示 "写入失败" 红色 Toast



### 4.10 调试信息栏

App 底部固定一个可折叠的调试控制台, 显示来自 MCU 的调试信息。

#### 协议

新增 `DEBUG_MSG` (CMD=0x80), MCU 主动推送或 App 轮询:

```
App 发 GET_DEBUG  (0x82) -> MCU 回复 DEBUG_MSG (0x80): [level:u8][count:u8][text...]
```

## 五、典型电赛工作流

### 5.1 赛前准备

```
1. 连接:
   上位机 → BLE 扫描 → 连接小车 CH9141BLE2U

2. 参数校准:
   打开参数编辑器 → 实时调整 PID 参数
   遥控小车跑几圈 → 观察速度曲线
   → 找到最优 PID → [保存到 Flash]

3. 传感器校准:
   灰度白校准 (Key1 长按)
   IMU 零偏校准 (Key2 长按)
```

### 5.2 示教编程

```
1. 开始录制:
   [开始录制] → MCU 以 20Hz 推送遥测
   上位机实时显示轨迹

2. 手动走赛道:
   用摇杆遥控小车跑一遍完整赛道
   上位机自动记录编码器轨迹

3. 标记航点:
   在关键位置 (路口/终点) 按 [记录航点]
   或在转弯处自动检测 yaw 变化来标记

4. 编辑航点:
   查看航点列表 → 调整位置/速度/延时
   插入 LINE_FOLLOW 航点启用循线

5. 保存:
   [保存到文件] → 导出 JSON
   [下发到小车] → 保存到 Flash
```

### 5.3 比赛运行

```
1. 上位机发 TEACH_LOAD(0) → MCU 加载预设序列
2. [开始回放] → MCU 自主执行航点
3. 上位机实时监控遥测数据
4. 必要时发 PAUSE/ABORT 中止
```

## 七、关键技术要点

### 7.1 CH9141 注意事项

- 出厂默认就是 **从机模式、115200、8N1**，无需 AT 配置即可使用
- RX 缓冲区 512 字节，单包不超过 256 字节
- 蓝牙未连接时 MCU 发过来的透传数据**会被丢弃**
- 建议 MCU 端在透传模式下不要频繁进 AT 模式（进 AT 会丢数据）
- 连接状态可通过 `AT+BLESTA?\r\n` 查询

### 7.2 MSPM0 性能考虑

- 协议解析在 ISR 中只做**字节喂入**，不做包处理
- 完整包的解析在**主循环 10ms** 中执行
- 遥测帧发送: 20Hz × 18 字节 = 360 B/s，UART 115200 带宽充足
- Flash 写入有寿命限制 (约 20K 次)，**只在用户主动点击"保存"时写 Flash**

### 7.3 App BLE 开发注意事项

- Android 需要位置权限扫描 BLE (6.0+), iOS 13+ 无需额外权限
- CH9141 不需要配对码，直接通过 GATT 连接
- 写操作用 `WriteValueWithResultAsync` 确保送达 (flutter_blue_plus)
- 通知(NOTIFY)需先写 CCCD (0x2902) 使能
- 断开连接后需 dispose 设备对象，否则再次连接可能失败
- 协议编解码状态机与 MCU 侧 `ble_protocol.c` 完全一致
